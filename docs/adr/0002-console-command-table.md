# Split the console dispatcher into a command table + domain modules

`main/uwatch_main.c::debug_process_cmd` was a single ~740-line function dispatching all 59 console commands via a flat `strcmp`/`strncmp` chain, mixing three inconsistent matching styles (exact string, prefix+argument, and multiple full-string checks for what were really one command with sub-verbs, e.g. `"motor"`/`"motor cal"`/`"motor calrestore"` as three separate rows). Four commands (`rec`/`playrec`/`tonerec`/`sweep`) shared invisible file-static state, and `tonerec`/`sweep` duplicated ~90 lines of play+record+peak-scan orchestration each. We're replacing it with a single `{name, handler}` table in `uwatch_main.c` (uniform first-token match, remainder handed to the handler as a raw string) with handlers pulled into separate modules only where real state or logic concentrated: `debug_audio.c` (the audio-test group, now sharing one `play_and_record()` orchestration implementation instead of duplicated code, with the recording state explicit file-statics owned by this module instead of hidden globals scattered in `uwatch_main.c`), `debug_bhi.c` (BHI260AP debug/tracing, including the `wudis` bitmask-to-sensor-group domain knowledge, kept console-local rather than promoted into the driver), and `debug_gnss.c` (calibration/seeding/tracking logic). The remaining ~30 thin pass-through commands (SD, crash, motor, power, alarm/RTC, BLE) stay together in `debug_cmds.c` — no dedicated file per domain, since nothing concentrates there worth a seam.

## Considered Options

- **One file per domain group uniformly** (9 files, including groups with a single thin pass-through command): rejected — sprawl for sprawl's sake; the deletion test on commands like `gnss`/`ble`/`motor` shows deleting them just removes a print path, nothing reappears elsewhere, so they don't earn a dedicated module.
- **Keep the mixed exact/prefix matching convention**: rejected — the dispatcher itself would still need two match modes, keeping the ad hoc character this refactor is meant to remove. Uniform first-token dispatch means every sub-verb command (`motor cal`, `track stop`, `bat on`) is one table entry whose handler parses the remainder, matching the already-settled self-parsed handler shape.
- **Promote `wudis`'s bitmask-to-sensor-group mapping into `bhi260ap.h`/`.c` as a first-class driver API**: deferred, not rejected — it's genuine domain knowledge with nowhere else it currently lives, but this pass is scoped to the dispatcher's structural problems (duplication, hidden state, matching inconsistency), not a driver-API audit. Flagged for a future pass.
